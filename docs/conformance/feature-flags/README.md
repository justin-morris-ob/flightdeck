# Feature flags — implemented local behavior

Flightdeck lets an authorized local operator manage environment-local flag metadata/lifecycle and publish typed configuration, ordered targeting, reusable audiences and scoped overrides. Segment drafts are separate from current publication; published references follow together after explicit segment review/publication. Master observes reported environments read-only. Separately authorized consumers evaluate within project/environment/tenant grants using trusted context, not an evaluation-time directory lookup.

[Current requirements](requirements/stage-two.md) define the unified replacement and retained evaluation/consumer behavior. [Unified verification](../../stage-two-verification.md#unified-redesign-verification) records exercised local checks and browser evidence; requirements alone are not proof. [Stage 1 requirements](requirements/stage-one.md) retain the historical security baseline. Earlier Stage 1/2 evidence remains historical and does not certify the replacement.

The management identity picker and consumer lab personas are synthetic and loopback-only. Backend-asserted traits and credential tenant grants are not production sign-in or independently verified BC membership. Optional BC directory authoring now supports scope-bound live lookup and ordinary guarded predicates, separately from the authenticated BC consumer adapter and without an evaluation-time directory dependency. The supported directory credential API is a separate BC PR prerequisite, not a released BC capability. Experiment measurement, shared-environment deployment and production identity remain outside the implemented scope; connected recording/runtime evidence is not inferred from implementation.
